# Workflow Diagram 一键成图（静态 + 动画）

目标：从业务内容到终稿一次走通"既清晰又美观"，不经历多轮审美返工。方法论来自 20260813 复盘
（`developlog/reviews/WORKFLOW_DIAGRAM_POSTMORTEM_20260813.md`）：
**拓扑与视觉都要动笔前冻结；手绘草稿阶段的逻辑梳理是可显式化、可自动化的；风格小样先行；几何先算后画。**

全程铁律：**一切修改只改生成脚本再渲染，永不手改 .drawio 文件。**
为什么（理解后再执行，不是刻板规矩）：
①单一真源——手改后文件与脚本双向漂移，下次重新生成会静默覆盖手改内容，且无人知道丢了什么；
②图的几何纪律（连线两端绝对 y 相等、轨线对齐、框体齐平）是**算出来的**，手拖一个框就会引入
肉眼拖不出、但渲染图上可辨的 1~2° 斜线；
③批量变更（全局字号、配色、箭头制式）只有改脚本常量才做得动，手改几十处不可审查、必漏；
④脚本 diff 可读、drawio XML diff 不可读，跨会话移交靠"脚本 + handover 文档 = 全部状态"；
⑤内嵌光栅层（`%3B` 编码的 data URI）在 GUI 保存时有被重写破坏的风险。
一句话：产物可无限重新生成，所以修改只能发生在生成它的那一处。

流程总览：Phase -1 逻辑梳理（文档→拓扑，替代手绘草稿）→ Phase 0 拓扑确认 → Phase 0.5 视觉系统冻结
→ Phase 1 布局数学 → Phase 2 风格小样 → Phase 3 脚本生成 → Phase 4 渲染自检 → Phase 5 迭代纪律
→ Phase 6 动画多页版（静态定稿后）。

## Phase -1：逻辑梳理（从业务内容到拓扑，替代手绘草稿）

手绘草稿的绘制成本本质是这一步的隐性思考。没有草稿时，按下面九步直接从文档产出拓扑；
有草稿时，按同样的框架**逆向解读**草稿（认出层/链/网格/语义形），与用户确认理解后再电子化——草稿只提供拓扑，不提供审美。

1. **要素抽取**：通读内容真源（文档/需求/访谈记录），列五类清单——角色（谁发起/谁受益）、
   程序（加工/分析动作）、数据（查询/回答/报告等流转物）、阶段（时间或因果先后）、回路（反馈/优化闭环）。
   每个要素标注出处章节，防臆造。
2. **分层（默认两层；世界观层需用户拍板才加）**：
   - 主链路层（怎么做）：单一主流向（默认左→右），一条主线贯穿全图；
   - 注解层（靠什么）：方法论、采集标准、量化口径（"×3平台×2地域×2遍"），集中放留白区，不进流程框；
   - 世界观层（为什么/元循环）：**默认不画**。盛邦定稿即无此层——手绘草稿顶部的元循环
     （消费者查询 ⇄ AI搜索回答 ⇄ 信源内容优化）连同图例、平台名、呼应虚线被整层删光。
     教训：不直接服务读者理解主链路的"价值叙事"元素都是删减候选；只有用户明确要讲故事时才加，
     且只放顶部独立一行、虚线降级呼应。
   - 梳理时若识别出回路/闭环，先问用户要不要世界观层，不要替用户加。
3. **泳道网格定骨架**：列=阶段（Step 1..N），行=数据链/服务链（并行分支各占一行）。
   **先定网格坐标再放框**——零交叉是网格的自然结果，不是事后修补出来的。
4. **数据链数 = 核心环节的并行输出类别数**：核心环节有几类输出就拉几条平行横链，一链对应一个下游服务/交付物。
5. **核心黑盒展开**：用户看不见内部但恰好是卖点的环节（如"AI 问答"），用内部结构表达
   "分流 → 并行处理 → 汇聚成答"；优先**隐含几何语义**（对称分区/对角线/边界形态），不堆编号和箭头。
6. **前后/对比关系 = 平行双轨**：优化前/后、对照组/实验组画等距平行线，不并线、不合流、不汇流排。
7. **形状语义化**：数据/产物一种形（胶囊/圆角），程序/环节一种形（尖角矩形），全图一致；需要才配图例。
8. **文字精简到名词短语**：框内只留主干名词；每个词过一遍"删掉会丢信息吗"；
   方法论与量化口径全部下放注解层；简写以读者（非作者）能懂为准。
9. **产出拓扑规格书**：节点清单、连线清单（从哪个框出、进哪个框）、泳道/阶段划分、锁定轨线、
   每框逐字文字 + 可选 ASCII 草图 → 交用户确认。**这份规格书就是手绘草稿的替代品**。

### 输入 = 签字报价单时（典型场景：报价单附图/服务示意图）

拓扑直接按报价单结构推导，不要凭空发明：

- **服务项目录 → 数据链与阶段**：每项服务 = 一条横链或一个阶段环节；服务间的数据依赖
  （如"可见性指标 → GEO 试点"）= 跨链连线。服务项目数/名称随客户变化，拓扑必须重新推导，
  **禁止照抄上一客户的图改 logo 充数**。
- **附录方法论 → 注解层 + 程序框文案**（如"SEC 消费心理学 × 九维消费认知模型"）。
- **查询集附录 → 数据节点**：原词集/优化集各一个节点；"选 N 条进哪个服务"的选取规则 = 路径标注
  （用独立 text 单元，不用边标签）。
- **执行参数 → 采集标准注解**：量化乘法表达（"每条查询 × N平台 × M地域 × K遍 ＝ 总数条问答轨迹"），
  不画啰嗦的逐实例标号。
- **前后对比类服务 → 平行双轨**（优化前/优化后，见第 6 步）。
- 报价单里没有的元素（世界观/元循环/图例）不要替客户发明。

## Phase 0：拓扑确认（不画图）

1. 拓扑规格书给用户确认；有歧义处列成二选一问题，一次问完。
2. 若用于汇报/动画，同时给分镜脚本（N 步揭示顺序），拓扑与动画共用，零返工。

## Phase 0.5：视觉系统检查单（动笔前必须冻结）

把下面这张表连默认值一起抛给用户，用户说"默认"就直接用，**不允许带着未拍板的视觉系统开画**：

| 项 | 默认值（deck 级，已验证） | 必须问清的 |
|---|---|---|
| 展示场景 | 16:10 2K 屏全屏投影 | 决定字号下限：图内字号 × (屏宽/图宽) ≥ 14 屏幕 px |
| 配色 | ≤2 个低饱和色相按语义分工（核心技术=浅紫底#EFEAF6+深紫字#4A1B75；交付物=浅青底#E3F2EF+深青字#0F766E；中间数据=灰白#F3F5F8）+ 1 个功能红#C00000 只做编号/标记 | 有无 VI 指定色；**色底白字、大面积彩填默认被否** |
| 质感 | 浅底深字、零阴影、零描边 | 阴影/渐变是否接受（默认否） |
| 形状语言 | 数据=胶囊(arcSize=50)，程序/环节=尖角矩形，竖条=HTML 表格多列竖排 | — |
| 连线 | 横平竖直、零交叉；箭头=纯黑 2px 开口箭头(endArrow=open;endFill=0;endSize=16) | 有无必须保留的旧制式 |
| 字号 | 说明/标注、节点标题、阶段标题 三档统一（同等级必须同字号），按展示场景算下限 | "图里最小能接受多大字" |
| 反面清单 | 请用户列举"一定不要"的（阴影？彩色？圆角？emoji？） | 比正面描述更能防返工 |
| 参考图 | 请用户给 1 张"就要这种感觉"的图 | 有则审美一轮收敛 |

## 审美与设计原则（全阶段适用）

- **网格对齐**：同链同高、同列同宽、间距成规律（等距或 1:3:1 类简单比例）；底边/顶边齐平优先。
- **呼应**：语义相关靠 同位（同 y/同 x）+ 同形 + 同色 呼应；不用底色带、大括号（廉价感来源，被否过"肤浅"）。
- **层级 ≤3 档**：阶段标题 > 节点标题 > 说明注解；每档字号统一，同等级必须同字号。
- **色彩语义化**：颜色 = 角色分工（核心技术/交付物/中间数据各一色族），不是装饰；≤2 低饱和色相 + 1 功能色；浅底深字。
- **流向单一**：主流向一个方向；回路走顶部/底部独立通道、虚线降级，不与主流穿插。
- **零交叉、零斜线、零超框**：必然交叉的线改框内文字明示或调整拓扑，不硬绕。
- **留白是构图元素**：核心黑盒周围留呼吸空间；注解集中放留白区；宁可删元素，不要塞满。
- **少即是多**：每个元素问"删掉丢信息吗"——世界观元循环、编号圈、图例、服务长标签、"从xx到xx"大标题、AI 味总结句都被删过。

## Phase 1：布局数学（先算后画，渲染前消错）

- 定画布与网格：行=泳道/服务链、列=阶段；先定若干条**锁定轨线**（关键横线 y 值），所有相关框对齐轨线。
- **文字尺寸预算**：每框必填文字 → 宽=最长行字数×字号，高=行数×字号×行距；竖排高=字数×字号。
  放不进就改文案或改形态（横排双行/多列竖排），不允许画出来再爆框。
- **通道可行性论证**：每条跨行/跨列连线在网格上推一遍，数学上必然交叉的不要硬绕——
  改用框内文字明示、编号圈、或调整拓扑，并写明取舍原因。
- **连线水平性**：drawio exit/entry 是相对分数，每条横线心算两端绝对 y 核对相等，否则出 1~2° 斜线（肉眼可辨）。

## Phase 2：风格小样（把审美轮次压到 1~2 轮）

1. 选全图视觉密度最高的 1 个区域，按冻结的视觉系统、**最终字号**渲染小样。
2. 若用户对口味的把握不明确，给 2~3 套配色/风格变体同区对比，让用户指一张。
3. 小样确认 = 视觉系统冻结，之后全图只允许几何调整，不允许再推翻风格。

## Phase 3：脚本化生成

- 单文件 Python 脚本生成 drawio XML。参考实现（已验证工具函数可直接抄）：
  `client-sbaq/make_workflow_drawio_v4.py` —— `add/add_edge/edge_style`（绝对坐标+端点分数）、
  `vtable/vcol_text`（HTML 表单格多列竖排，拉丁合并一行、CJK 逐字一行、整格可拖动）、
  `arc_pts/circle_pts`（圆周采样画真圆弧）、`xflow_png_b64`（SVG→cairosvg 3x PNG→base64 内嵌）。
- 复杂图形（渐变/任意闭合形/手绘 icon）：脚本内拼 SVG → cairosvg 光栅化 3x PNG → 内嵌，源文件保持自包含。

## Phase 4：渲染与自检（用户只见通过自检的稿）

1. 渲染（本机已验证）：`python3 make_xxx.py && xvfb-run -a drawio --export --format png --scale 2 xxx.drawio -o out.png`
2. **自检清单**（全过才给用户看）：
   - ReadMediaFile 全图 + 逐区 1:1 截图回读，检查：文字超框、遮挡、斜线、交叉、对齐、字号档位一致；
   - 脚本侧几何断言：连线两端绝对 y 相等、框体不重叠、文字预算复核；
   - 对照 Phase 0 拓扑规格书逐线核对（漏线/错接）。
3. 自检发现的问题修完再渲染复检，**用户只判审美，不该抓到几何 bug**。

## Phase 5：迭代纪律

- 用户反馈打包处理：一轮反馈全部落地 → 渲染 → 自检 → 再给用户；禁止改一处渲一次。
- 维护 handover 文档：当前坐标真值表 + **被否路径清单**（防止自己或下一会话重新提议已否决方案）+ 出图命令，每轮同步。
- 高危变更预警：改名变长、全局字号变更必然引发重排——先做影响面评估（哪些框/线/轨线受牵连）再动手。
- 跨会话续作第一步：问清"不满意"具体指哪个区域，禁止盲目全局重做。

## Phase 6：动画多页版（静态终帧定稿之后）

**动画 = 静态终帧的递进揭示，不是另一张图。** 拓扑/坐标/视觉系统的单一真源仍在静态脚本。

设计原则：

- 分镜 = 读者理解顺序：每次揭示一个语义块（一条链 / 一个服务 / 一个阶段），每页一条标注条
  （「分镜 n/N ｜ 本页讲什么」），最后一页 = 完整终帧、无标注（GIF 里末帧加长停留，如 8s）。
- 已确认的业务口径要落在分镜节奏里（如"优化后线滞后到 GEO 执行后才流入"= 该线单元在对应页才出现）。
- **闪光链路表达回路/第二轮**：在已揭示的拓扑上，用一串纯高亮帧（无新增单元）表达"再跑一轮"的因果传播——
  执行框闪 → 回流边出现 → 采集平台再闪 → 输出闪 → 指标框闪 → 结果回流。读者看着高亮沿链路走一遍，
  比任何文字都直白。高光只闪一页、次页恢复常态；闪光帧与少量真实新增单元（回流边）穿插排布。
- 世界观层不进分镜（与静态定稿一致）。

技术要点（已验证，参考实现 `client-sbaq/make_workflow_drawio_v4_anim.py`，18 页版）：

- 动画脚本运行时 `importlib` 导入静态脚本，取终帧 `cells` 全集；`STEPS` 表每行 =
  （页名， 新增单元 id 列表， 标注文案， 本帧闪光单元 id)；每页 = 终帧单元按 z-order 过滤出的**累计子集**
  + 标注条 + 本帧闪光替换。改分镜只改 STEPS 表。
- **覆盖性断言**：各页新增单元的并集必须恰好等于终帧全集（无遗漏、无未知 id），脚本启动时 assert——
  这是"动画与静态永不漂移"的机制保证（闪光帧新增为空，天然不破坏断言）。
- **通用闪光 `flash_cell()`**：正则把单元 style 的 `fillColor` 换闪光深紫 `#8A63C9`，`fontColor` 与 value 内联
  `color:` 一起改白；不动 strokeColor；无 fillColor 的纯文本单元闪不了（别选它做高光）。
  复杂装饰层（如 X 框内嵌 PNG）单独做一版闪光配色 PNG 整体替换 + 配套标签改白。
- 每页首格放全透明 anchor 矩形撑满画布 → 各页导出同尺寸，翻页/GIF 不跳帧。
- 导出坑：`--all-pages` 对 PNG 只导第一页，必须 `-p` 逐页导：
  `for i in $(seq 1 N); do xvfb-run -a drawio --export --format png --scale 2 -p $i xxx-动画.drawio -o anim/anim-$(printf %02d $i).png; done`
- GIF 组装：`convert -resize 1400x -delay 120 -loop 0 anim/anim-*.png anim/anim.gif`；
  末帧加长停留 = 对末帧单独设更大 delay（ImageMagick `-delay` 可按帧分组设置，如末帧 800）。
- 交付双形态：多页 .drawio（drawio desktop 翻页播放、可编辑）+ GIF（文档/微信嵌入）；逐帧 PNG 留档便于复检。
- 动画的自检 = 逐帧 ReadMediaFile 回读：揭示顺序正确、无单元提前/缺席、闪光恰好一页且次页恢复、标注无遮挡、帧间尺寸一致。

## drawio 无头导出坑表（本机 drawio 31.1.8 实测，勿再试错）

- **内嵌图不渲染**：`image=data:image/...;base64,...` 空白（style 串按 `;` 切分，`;base64` 把值截断）；
  `file://` 引用也空白。唯一可行=分号 URL 编码：`image=data:image/png%3Bbase64,...`，SVG 先 cairosvg 光栅化。
- **边标签（value+bglabel）的 y 偏移落点不可靠**（会盖框标题）：路径/连线说明一律用独立 text 单元放验证过的空白处。
- `curved=1`+少量控制点弧线发闷：用圆周采样（≥40 点或 5 点折线起）画真圆弧。
- 圆弧法线公式：`nx,ny = -dy/L, dx/L`（第二分量是 dx 不是 dy，写错弧退化成直线）。
- exit/entry 是相对分数：框一动就要重算受影响的连线端点。
- 整页截图/flatten 类后处理勿用；本链路就是直接无头导出 PNG。

## 完成定义

- 用户明确认可终稿；`.drawio` 源文件可编辑自包含（drawio desktop 直接打开可改）；
  生成脚本、产物 PNG、handover 文档三件套齐全；拓扑规格书、视觉系统、被否清单记录在案。
- 有动画时：动画脚本、多页 .drawio、逐帧 PNG、GIF 四件套齐全，覆盖性断言通过，逐帧目检通过。
