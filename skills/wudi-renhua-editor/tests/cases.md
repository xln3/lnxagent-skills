# 回归测试用例

这些用例用于修改本 Skill 后做行为检查。重点是“应该如何处理”，不是固定唯一答案。

---

## Case 1：典型去 AI 味

### 输入

```text
用无敌人话修改，标准改写，只给正文：

随着人工智能技术的快速发展，企业越来越重视数据价值。数据不再只是静态资源，而是驱动业务增长的核心引擎。企业需要从技术、管理、人才和文化多个维度出发，构建数据驱动的增长闭环。
```

### 必须做到

- 删除宏观空开头。
- 拆掉“不再只是……而是……”。
- 不保留四维假全面。
- 不编造任何企业案例或数字。
- 若缺少具体上下文，收紧成一段准确、有限的表述。
- 只给正文。

### 禁止

- 用另一组空话替换。
- 加“在当今时代”。
- 擅自生成数据治理流程细节。

---

## Case 2：真实纠错中的“不是……而是……”

### 输入

```text
润色，但不要删除必要的对比：

我以为 curl -I 访问失败是网络不通。其实不是网络问题，而是这个页面不支持 HEAD，只允许 GET。
```

### 必须做到

- 保留真实纠正关系。
- 可压缩措辞，但不能机械去掉否定对比。
- 不扩写无关 HTTP 科普。

---

## Case 3：承诺强度

### 输入

```text
改得自然一些：

项目预计在 9 月底完成首轮测试，但不保证全部平台届时都能稳定采集。
```

### 必须做到

- 保留“预计”。
- 保留“不保证”。
- 不改成“将在 9 月底完成”。
- 不改成“争取完成”。

## Case 4：合同边界

### 输入

```text
去官腔，但保持法律含义：

如甲方新增或调整评测问题集、目标平台、地域范围等评测需求，双方应就新增服务范围及费用另行确认。
```

### 必须做到

- 保留触发条件、双方责任和另行确认。
- 可精简，但不能改成口语承诺。
- 不增加“书面”或“提前”等原文没有的要求。

---

## Case 5：已经自然

### 输入

```text
改成人话：

这个 403 已经说明请求到了上游。问题更可能是模型通道没额度，不是本地代理断了。
```

### 必须做到

- 只做最小修改或原样保留。
- 不为了显示工作量扩成五段。
- 不加背景和排查清单。

---

## Case 6：技术术语不可简化

### 输入

```text
改得更自然，保留技术精度：

REMU 通过 VA→PA→DRAM 双向映射恢复故障位在 LPDDR4 组织中的位置，并使用 bitmap-tree 索引可注错位点。
```

### 必须做到

- 保留 VA、PA、DRAM、LPDDR4、bitmap-tree。
- 不把“双向映射”改成“地址转换”而丢失含义。
- 可调整句法，但不能科普化扩写。

---

## Case 7：证据不足

### 输入

```text
重写得更有说服力：

我们的产品能够显著提高所有企业的运营效率，是行业领先的解决方案。
```

### 必须做到

- 不补造百分比、客户数、排名或案例。
- 收紧“所有企业、显著、行业领先”。
- 可以指出需要什么证据，但默认输出仍应是可用正文。
- 不用更华丽的口号掩盖证据不足。

---

## Case 8：个人声音

### 输入

```text
改自然一点，但别把我的态度磨平：

第二张就是更好。第一张看着精致，实际上把先后关系画错了；这种图再漂亮也不能交给客户。
```

### 必须做到

- 保留明确判断和锋利程度。
- 不改成“两张各有优势”。
- 可修节奏，不消毒语气。

---

## Case 9：商业体裁

### 输入

```text
改成客户能看懂的报价单服务说明：

我们将通过智能化、多维度、体系化的评测能力，全面洞察品牌在 AI 搜索中的认知表现，并赋能后续优化。
```

### 已知上下文

18 问题 × 3 变体 × 3 平台 × 2 地域 × 5 轮；交付提及率、Top1/3/5、推荐位置和竞品对比。

### 必须做到

- 使用已知规模和指标。
- 写成交付可验收的服务内容。
- 不保留“智能化、多维度、体系化、赋能”。
- 不增加上下文没有的平台名。

---

## Case 10：学术边界

### 输入

```text
去 AI 味：

实验表明该方法有效，因此能够全面解决星载 AI 的可靠性问题。
```

### 必须做到

- 指出或修正结论超出实验范围。
- 若没有实验细节，不编造结果。
- 可改成“结果支持该方法在所测试场景中的有效性”一类有限结论。
- 不保留“全面解决”。

---

## Case 11：引用不改

### 输入

```text
重写这段说明，但引号内原文保持不动：

日志返回“Sorry, there are currently insufficient promotional resources”，说明请求已经进入上游模型服务。
```

### 必须做到

- 引号内完全不改。
- 只修改外围说明。
- 不翻译或纠正引语。

---

## Case 12：代码块不改

### 输入

````text
改成人话，命令原样保留：

你可以使用下面的命令来对服务的可访问性进行相关测试：

```bash
curl -sS -L -D - -o /dev/null http://127.0.0.1:9090/ui/index.html
```

通过该命令，我们能够进一步判断服务是否正常运行。
````

### 必须做到

- 代码块原样保留。
- 删除“进行相关测试、通过该命令我们能够进一步”。
- 改成直接的操作说明。

## Case 13：诊断而非重写

### 输入

```text
只分析为什么像 AI，先不要改：

这不仅是一次升级，更是一场面向未来的价值重构。
```

### 必须做到

- 使用 `[模板]`、`[逻辑]`、`[空心]` 中最相关标签。
- 说明 A/B 不一定递进、B 缺乏定义。
- 不输出完整修改稿。
- 不断言一定由 AI 生成。

---

## Case 14：只要正文

### 输入

```text
标准改写，只要正文，不要任何解释：

值得注意的是，该结论只适用于北京和上海，不能直接推广到其他地区。
```

### 期望方向

```text
该结论只适用于北京和上海，不能直接外推到其他地区。
```

### 禁止

- “修改后：”
- 引号
- 解释
- 后续邀请

## Case 15：多个版本必须真正不同

### 输入

```text
给我三个版本：更直接、更克制、更有品牌感。

当智能体犯错时，我们需要知道发生了什么。
```

### 必须做到

- 三个版本使用不同表达策略。
- 事实一致。
- 品牌感版本仍需具体，不写“守护未来、信任底座”空话。
- 不只是替换“需要 / 必须 / 应当”。

## Case 16：强行口语化防护

### 输入

```text
改成人话，用于正式汇报：

说白了吧，这个系统其实就是帮我们把各种东西都整到一起，然后更方便地看问题。
```

### 已知上下文

系统统一保存查询、回答、引用 URL、平台、地域、账号和轮次。

### 必须做到

- 去掉表演式口语。
- 使用已知字段具体化。
- 保持正式但直接。
- 不重新写成“构建统一数据中台，赋能洞察”。

---

## Case 17：列表不必凑三点

### 输入

```text
改写并重新组织：

项目当前有三个主要问题：第一是模型版本不固定；第二是账号状态不稳定；第三是需要进一步加强团队沟通。
```

### 必须做到

- 判断第三项是否与前两项同粒度。
- 将真实技术阻塞优先。
- “加强团队沟通”若无具体内容，应删除或改为责任分工（仅当上下文提供）。
- 不保留三点只是为了整齐。

---

## Case 18：原文中的有意排比

### 输入

```text
轻改，保留演讲节奏：

让事故看得见，让过程说得清，让责任追得到。
```

### 必须做到

- 识别为有功能的简短排比。
- 原样保留或仅做极小修改。
- 不机械拆成说明句。

---

# 通过标准

回归测试至少满足：

- 所有硬性语义用例通过；
- 不出现编造；
- “不是……而是……”既不会滥留，也不会机械删除；
- 能区分正式、技术、商业、个人和演讲体裁；
- 能在“已经自然”时少改；
- 能严格遵守“只给正文”；
- 能处理证据不足和承诺强度。
