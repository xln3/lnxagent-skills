# 跨 Agent 会话插件：宿主原生日志架构（draft v0.3）

状态：当前推荐架构。本文记录用户在第 2 轮明确的形态决定，并替代 v0.2 的第 5 节和第 8 节；v0.2 的真实 DSH 样本、完整性边界和体积实验继续有效。

实现进展：DSH 首个纵向切片及其能力审计见 [draft v0.4](session-ledger-implementation-v0.4.md)；真实 Web UI、compact、异步子会话、附件与接收 Agent 续跑的端到端验收见 [draft v0.5](session-ledger-dsh-acceptance-v0.5.md)，第 8 节 MVP 的 DSH 闭环已关闭。Codex、Kimi Code、Claude Code 适配器尚未开始。

## 1. 已拍板的两个边界

1. **每家 Agent 的原生日志就是正文事实源。** DSH、Codex、Kimi Code、Claude Code 各自使用自己的 session 记录，不转换成另一套完整正文账本。
2. **这个工具是宿主内插件，不是独立采集器。** 插件随 Agent 会话运行，通过宿主扩展点发现会话、读取原生事件、维护导航关系并生成复盘或交接视图。

共享能力放在通用核心库，宿主差异放在各 runtime 的薄插件适配器。不是要求同一个插件二进制能直接加载进所有宿主。

## 2. 架构

```text
┌─────────────────────────────────────────────────────┐
│ 各 Agent 宿主                                        │
│                                                     │
│  DSH 插件   Codex 插件   Kimi Code 插件   CC 插件    │
│     │           │              │              │     │
│     └───────────┴──── 宿主扩展点 ─────────────┘     │
│                         │                           │
│                各家自己的原生日志                    │
│                （唯一正文事实源）                    │
└─────────────────────────┬───────────────────────────┘
                          │
                共享只读解析与投影核心
                          │
        ┌─────────────────┼──────────────────┐
        │                 │                  │
   完整复盘视图        续跑交接视图        按需导出包
```

通用核心库只负责：

- 识别宿主和原生格式版本；
- 把原生事件映射为视图所需的统一分类，不改写原始正文；
- 分别重建完整历史和当前有效上下文；
- 解析父子会话、fork、compact、工具调用和附件引用；
- 生成 `review.md`、`handoff.md`、HTML 或导出 manifest；
- 报告格式不识别、事件缺失、附件缺失和未覆盖能力。

## 3. 插件做什么

### 3.1 会话生命周期

- 在 `SessionStart` 或宿主等价入口获得 session id、agent id、cwd 和原生日志位置。
- 订阅宿主已有事件，用于刷新视图、更新父子关系和使缓存失效。
- 在会话结束、compact、fork、子智能体创建和恢复时更新导航元数据。
- 需要导出时先调用宿主已有的 flush/checkpoint 能力，再读取一致快照。

### 3.2 只读使用原生日志

- 正文始终从宿主原生日志读取。
- 统一事件分类可以存在于内存、视图或一次性导出索引中，但不成为第二事实源。
- 插件缓存只保存位置、索引和展示状态，删除后必须能从原生日志完整重建。
- compact 后继续从原生日志读取旧事件，不能用插件摘要替代历史。
- 子智能体使用宿主自己的 session id 和父子关系，不另造一套 agent 身份。

### 3.3 按需生成产物

- 复盘时生成完整时间线，包含被 compact 遮蔽但仍存在于原生日志中的事件。
- 交接时生成全部人类要求原文、当前有效上下文、未完成事项和来源链接。
- 导出时才把原生日志快照复制进交接包，并记录哈希和格式版本。

“导出时复制一份”是为了离线移动，不等于运行期间维护一个平行镜像。插件平时不写第二份正文。

## 4. 插件不做什么

- 不维护独立的 `sources/` 原生日志镜像目录作为长期运行时存储。
- 不写 `payload + source.raw` 双份事件。
- 不把 hook 收到的所有正文再写进自己的 NDJSON。
- 不依赖独立守护进程、终端包装器或文件跟随器才能工作。
- 不接管或替换宿主自己的 compact、resume、fork 和子智能体机制。
- 不伪造宿主未暴露的 reasoning、工具结果或外部副作用状态。
- 不把 SQLite、搜索索引或 Markdown 当作删除原生日志后的替代品。

## 5. 原生格式缺口怎么处理

插件能力不能超过宿主实际暴露的接口和日志内容。

1. 宿主已有原生扩展事件机制时，插件可以把自身需要的导航元数据写进该原生机制。
2. 宿主没有相应机制时，插件只保存最少量的会话定位、视图配置和缓存，不另存完整正文。
3. 原生日志本身缺少某类正文时，必须标记 `unavailable` 或 `uncovered`，不能用影子账本悄悄补齐后声称是宿主原生记录。
4. 某宿主无法提供只读日志、父子关系或一致快照时，在能力矩阵中明确限制，再为该宿主设计原生扩展方案；不能自动退回独立采集器。

因此，下一步必须分别验证 Codex、Kimi Code、Claude Code 和 DSH 的实际插件/钩子能力，不能预设它们具有相同 API。

## 6. 通用适配器边界

逻辑接口如下，具体语言和各宿主 API 另行确定：

```text
HostSessionAdapter
  capabilities()       -> 原生事件、子会话、附件、flush 等能力
  activeSession()      -> 宿主原生 session 引用
  readEvents(range)    -> 原生事件流，不做完整正文复制
  readChildren(ref)    -> 宿主原生父子引用
  readAttachments(ref) -> 宿主原生附件引用
  flushForExport(ref)  -> 使用宿主能力形成一致导出快照
```

共享投影层接收原生事件和统一分类映射，输出：

- `fullHistory`：历史上发生过什么；
- `currentSurface`：当前模型实际看到什么；
- `handoffState`：任务、工具、子 Agent 和工作区还缺什么；
- `coverage`：哪些内容可证明存在，哪些不可得。

统一的是读取和投影语义，不是另造一种正文存储格式。

## 7. 缓存与导出存储

### 7.1 运行期间

- 原生日志：宿主负责，插件不复制。
- 会话导航：优先使用原生关系；插件只补充必要的最小元数据。
- 索引/SQLite/全文搜索：可选、可删除、可重建。
- HTML/Markdown：按需生成，不默认持久化。

### 7.2 导出交接包

```text
handoff-package/
  manifest.json
  native/
    <runtime>/<root-session>/<原生文件>
    <runtime>/<child-session>/<原生文件>
  views/
    review.md
    handoff.md
  artifacts/                 # 仅原生附件需要随包移动时
  workspace/                 # 仅续跑需要时显式收集
```

manifest 至少记录 runtime、原生格式版本、session/agent id、父子关系、源文件哈希、附件哈希、适配器版本和覆盖缺口。导出索引只在确有导航需要时生成，不是强制正文层。

## 8. 修订后的 MVP

先实现一个 DSH 宿主内插件的纵向闭环：

1. 通过 DSH 插件入口获得活动 session，而不是扫描并镜像 `~/.dsh`。
2. 使用 DSH 原生 session/persistence 读取接口获得已提交事件。
3. 从原生事件生成完整复盘视图和当前 surface 交接视图。
4. 使用原生 compact、parentSession/origin 和附件机制，不另建正文记录。
5. 删除插件全部缓存后，能从 DSH 原生日志重新生成相同视图。
6. 导出时形成一致快照，导出的原生文件与宿主来源哈希一致。
7. 用一个真实任务验证：compact 前的要求仍可回看，子会话可递归打开，接收 Agent 能读取全部人类要求并继续小任务。

DSH 闭环后，再分别实现 Claude Code、Codex、Kimi Code 插件适配器；每个宿主先验证扩展点，再确定实现方式。

## 9. 验收指标

- **正文零双写**：运行期间插件数据目录中不存在完整对话正文副本。
- **缓存可删除**：删除插件缓存不损失任何原始会话事实。
- **来源一致**：导出快照与宿主 flush 后的原生日志哈希一致。
- **compact 可穿越**：完整复盘能读取被遮蔽的旧事件，当前上下文不误包含它们。
- **递归完整**：所有原生可见后代会话均可定位；缺失后代显式报错。
- **要求不缩水**：交接视图包含全部人类要求原文，不以摘要替代。
- **能力诚实**：reasoning、附件、未 settle 流和外部状态按宿主实际能力标记。
